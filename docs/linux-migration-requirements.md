# Linux 迁移要求

状态：依据用户已确定的跨平台体验一致原则制定的迁移要求与验收基准。
确定日期：2026-10-18。
产品基线：macOS `0.6.1+2`；Linux 在 `codex/linux-desktop` 分支开发。

## 一、总原则

**各平台必须保持与 macOS 一致的核心用户体验。迁移交付的是同一个 Vocal More 产品，不是一个功能相近、操作方式不同的 Linux 演示程序。**

平台可以使用不同的系统 API、窗口实现、权限机制和发行方式，但用户完成同一任务的入口、步骤、反馈、结果和退出行为必须一致。Rust 业务核心与 GPUI Kit 路线保持不变，复用已经验证的原生音频与 DSP 能力。

“编译成功”“后端接口可调用”“隔离测试通过”“安装包可安装”均不是产品迁移完成的充分条件。验收必须包括安装后的实际桌面体验，并与 macOS 对照。

## 二、默认形态与启动、退出

1. 默认后台运行，通过系统状态栏/托盘及用户设置的全局快捷键使用。
2. **不得新增常驻“听写窗口”“录音控制台”或调试面板作为主要使用入口。** 现有 Linux 独立听写窗口不是 macOS 胶囊的等价实现，应从正常产品流程移除；开发验收工具不得混入默认启动流程。
3. 首次启动提供必要的初始化和权限引导；后续启动遵循 macOS 的窗口呈现规则，不重复打开无关窗口。
4. 设置窗口只在用户主动打开或确有初始化操作时出现。关闭设置不退出应用，不停止快捷键和胶囊服务。
5. 状态栏/托盘提供与 macOS 对应的常用操作，包括打开设置及退出。不得通过额外窗口弥补入口缺失。
6. 显式退出应结束音频、观察、屏幕采集和所属后台任务，保存已接受的修改；不得留下悬浮层或静默丢失设置。

## 三、悬浮胶囊：必须交付的主交互

1. 使用与 macOS 一致的深色 Dynamic Island 风格胶囊：形态、文字层级、波形、取消/完成操作和状态含义一致。
2. 开始录音时自动出现；连接准备、聆听、处理中、错误和结束状态与 macOS 对应。空闲成功结束后隐藏；终态错误按 macOS 的恢复/关闭规则处理。
3. 胶囊不得抢走目标应用的键盘焦点，不得改变光标或选区；点击取消/完成后仍能在原输入位置继续工作。
4. 在不同工作区、普通窗口、最大化/全屏及多显示器环境中提供与 macOS 相应的可达性；锁屏时隐藏，解锁后不得错误重现旧会话。
5. 波形与录音状态来自实际业务状态，不能以模拟动画冒充已采到音频；遵循减少动态效果设置。
6. **GNOME Shell 扩展只是平台适配细节，不能据此把“无胶囊、只有听写窗口”标为已完成。** 安装、启用、版本兼容、失联恢复和更新必须作为交付链路的一部分验证。
7. 系统限制导致需要用户授权、注销或重新登录时，应在应用内明确说明原因、当前状态及下一步；不得自动重启桌面或让用户自行排查扩展。限制解除前，相应能力仍为未验收状态。
8. 不支持的桌面环境必须明确标注范围，不得笼统宣称“Linux 胶囊已支持”。

## 四、快捷键：迁移 macOS 的界面配置方法

1. 设置中提供与 macOS 对应的快捷键页面，支持查看当前绑定、添加、按键录入、修改、移除、取消录入及反馈保存结果。
2. 用户通过 UI 完成配置后应全局生效并持久保存。**不得要求普通用户进入 GNOME 系统设置、编辑配置文件或执行命令来完成基本快捷键配置。**
3. 已在本机配置的 `F1` 必须被识别并显示，不能再创建一份重复绑定。
4. 录入期间不得触发实际录音；Esc、切换页面、关闭窗口或失去录入焦点应安全退出录入。长按产生的重复事件不得创建多条绑定或反复开始/结束录音。
5. 绑定冲突、系统保留按键、权限不足和保存失败应明确提示，保留原有效绑定，不能显示“已保存”但实际未生效，也不得覆盖其他应用或系统的快捷键。
6. 支持与 macOS 对应的录音手势和模式：按住说话/松开结束、短按进入免提及再次结束、取消等，按所选模式保持一致。当前用户选择的 `F1` 一键开始/结束必须继续可用。
7. 硬件键名可以符合平台习惯，如 Command/Super、Option/Alt；无法提供同一物理键或事件语义时，应提供产品内的等价操作并明确说明。不得把缺少按下/松开事件解释为该模式已经完成迁移。
8. 任何仍依赖系统快捷键的内部注册方式，都必须由应用负责接入、更新、移除及恢复；不能将实现细节变成用户操作步骤。

## 五、完整听写流程

目标流程与 macOS 一致：

> 保持目标输入框焦点 → 触发快捷键 → 胶囊反馈录音 → 完成 → 识别/润色 → 结果进入原输入位置 → 胶囊恢复空闲。

- 保留低声输入这一核心场景：增益、高通、软限幅、噪声控制、麦克风选择和预览均应在实际设备上验证。
- 模式切换、流式反馈、润色、双语和用户词典行为应与 macOS 对齐。
- 取消后不得继续输出晚到结果；切换输入目标、系统快捷键冲突或目标不可编辑时不能误插入其他窗口。
- 自动插入、流式插入和剪贴板恢复应提供与 macOS 一致的任务结果与安全边界。
- **当前 Wayland“复制后再按 Ctrl+V”是能力差距，不能作为 macOS 自动插入的等价验收结果。** 它可作为明确的临时降级方式；在解决并验收前，自动插入项保持未完成，不得隐去额外一步。

## 六、屏幕上下文

- 从设置与正常录音流程进入，与 macOS 对应；由系统授权选择采集范围，不绕过平台权限。
- 当前会话采集、编码、上传和识别使用真实画面；不得混淆模拟服务、真实云端和只验证传输的结果。
- 正确处理窗口裁剪、比例、缩放、屏幕切换、停止、取消、拒绝授权及退出清理。
- 图像只作为听写上下文使用，不能因测试问答探针成功就改变产品默认的“只输出所说内容”语义。
- 权限失败应给出可操作的恢复入口，不得静默显示为功能正常。

## 七、自动纠错学习

- 设置入口、启用/停用、候选提示、审核、拒绝、撤销及词典呈现方式与 macOS 一致。
- 观察实际输出的原目标及被修改片段，不读取新焦点的无关输入框，不学习密码、排除应用或用户未实际粘贴的内容。
- 本地证据、云端分类、策略判定、写入、持久化和撤销应逐层验证，并在正常产品操作中串联验收。
- 系统辅助功能不可用时，应提供与 macOS 对应的授权/诊断反馈，不能静默失效。

## 八、设置、历史与系统集成

- 设置页的信息架构、含义、默认值及反馈与 macOS 对齐，尊重系统明暗主题；只为必要的平台差异调整文案和权限入口。
- 历史、重试、播放、删除、词典编辑、服务配置与密钥保护均需迁移，不得通过独立脚本代替用户界面。
- 应用图标、桌面启动入口、重复启动、后台运行和托盘操作必须实际可用。
- 更新机制按用户已确定的 Linux 方案：**由 APT 管理，通过 `sudo apt upgrade` 更新，替代 Sparkle。** 此发行方式差异已获用户明确确认；不得引入应用内自行提权安装器。
- 仍有未实现能力或系统限制时，开发版必须明确标注，不能以 Linux 为由永久降低体验标准。

## 九、验收方式与完成标准

每个功能同时验证以下三层：

| 层次 | 必须证明什么 |
| --- | --- |
| 业务与回归 | Rust/Python 所需测试通过，原 macOS 行为没有被平台适配破坏 |
| 真实系统集成 | 使用真实快捷键、窗口、权限、音频、剪贴板、辅助功能和云端；明确模拟内容与实际服务边界 |
| 安装后的用户流程 | 从已安装应用出发，在用户桌面完成任务；入口、步骤、焦点、反馈、结果和退出体验与 macOS 对照一致 |

最少覆盖：首次安装、再次启动、后台空闲、快捷键录入与冲突、实际全局触发、胶囊所有状态、不抢焦点、两种录音模式、取消、原位输出、设置关闭后继续使用、屏幕授权/拒绝、纠错学习/撤销、显式退出，以及目标 GNOME/X11/Wayland 组合。

不得用下列结果代替产品验收：

- 仅看到测试胶囊截图，却没有在安装后的实际桌面出现胶囊。
- 通过系统手工配置 F1，却没有应用内的快捷键配置界面。
- 用常驻听写窗口按钮完成流程，却声称已经迁移 macOS 的后台/胶囊体验。
- 只验证模拟识别服务，却宣称真实云端链路完成。
- 需要手动粘贴，却宣称自动插入体验一致。

所有差距必须有明确状态与验收证据；不得以“功能大致可用”宣布迁移完成。
