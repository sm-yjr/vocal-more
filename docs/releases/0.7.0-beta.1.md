# Vocal More 0.7.0-beta.1 — Bluetooth development prerelease (build 3)

This is an **ad-hoc signed, unnotarized development test ZIP**, for Apple Silicon
Macs running macOS 14 or later. It is a separate application and profile; keep
it alongside your stable app. No automatic update feed is changed.

BLE carries completed text between the Macs. Keyboard shortcuts continue to use
macOS Universal Control; Bluetooth does not forward shortcuts or audio. Choose
local or peer output explicitly. Automatic UC focus detection remains blocked.

- Explicit code verification, encrypted GATT, connection-bound output and duplicate
  suppression protect against stale or repeated delivery.
- Current-app input is off by default and guards the focused field/caret, lock
  state and permissions. Keyboard paste fallback is reported as unconfirmed.
- Normal launch imports no credentials, opens no microphone, registers no global
  shortcut and exits after 15 minutes. Fixed-marker acceptance is the first step.
- Live dictation requires configuration in this isolated profile and an explicit
  `--enable-candidate-dictation` launch when ready. This mode runs until quit.

## Download and test

Extract the ZIP on each Mac and open `Vocal More Bluetooth Candidate.app`.
If the operating system blocks this unnotarized package, use the ordinary
Privacy & Security approval only under your organization's policy. Never disable
Gatekeeper or remove quarantine. Grant Bluetooth and, for receiving into another
app, Accessibility to this exact candidate when you choose to test those actions.

Make one Mac search and the other accept, compare both six-digit codes, and
approve the intended sender. Enable current-app input on the receiving Mac,
focus an empty test document and send a fixed marker. Test both directions and
reconnection before trying live dictation. See `docs/bluetooth-productization.md`
in the included corresponding source for the detailed sequence and limitations.

## Evidence and remaining gates

The remapped public build passed 108 Rust desktop library tests, 49 backend
tests, strict Rust/Python lint, native warning checks and the native pairing
state regression. The full Python run passed 1086 tests and skipped 11; its
single CoreAudio enumeration failure under sandbox passed when rerun outside
the sandbox (1 test), without opening an audio graph or recording. Backend
localhost mock tests likewise required permission to bind local sockets.
The implementation also passed headless Metal settings rendering before
public packaging; its runtime source is unchanged.
Automated tests do not establish physical Bluetooth or external-app acceptance.

**Not yet accepted with this build:** the company Macs, physical BLE transfer,
Typora or other external-app input, actual F1/UC behavior, microphone/provider
latency, sleep/wake, minimum macOS compatibility, Developer ID signing,
notarization and upgrade delivery. An older prototype's BLE timings do not
apply to this package. Two-stage correction is outside this prerelease.

## Isolated publication route

The display version is `0.7.0-beta.1` (bundle build 3). The deliberately separate
tag `bluetooth-test-070b1-build3` does not match the repository's normal version
tag patterns. This development prerelease is uploaded manually with
`prerelease=true` and `make_latest=false`. Existing release workflows, their
signing gates, main and shared Sparkle feeds are unchanged. This ZIP does not
claim completion of the official signed distribution process.

The uploaded source archive and build manifest identify the exact source commit,
locked dependencies, build commands and asset SHA-256 values. GPL-3.0-only and
third-party notices are included. Source changes are based directly on the
existing public main history; unrelated local artifacts are excluded.
